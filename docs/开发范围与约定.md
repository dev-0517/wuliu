# 华诺 MVP 开发范围与约定

## 需求来源

1. 模块拆分分析报告：五个模块和认证—案件—问答—历史—账号的主链路。
2. 图片参考：蓝白视觉、移动端交互、案件关联对话、材料清单与案情梳理。
3. 物料文档：DeepSeek、真实数据库查询、Axios、FastAPI、参考示例代码、适合初学者阅读。

用户已授权开始开发。文档中的建议不自动等于正式验收要求。以下为本轮实现范围，便于评审。

## 本轮实现取舍

保留五个模块，优先实现可运行闭环。参考图作为布局与流程参考，不做逐像素复刻。以“用户自己的案件”为主，避免将示例数据混同为真实案件。

本轮使用账号密码登录、SQLite 本地数据库、案件文字描述与材料清单。案情梳理和时间线使用当前记录生成并标明 AI 性质。未提供可验证胜诉率算法和真实律师审核机制，因此没有实现胜诉率和律师审核状态；需要增加时应作为独立需求讨论。

未接入文件上传、证据文件解析、文档归类与企业角色。LangChain 没有成为本轮依赖，AI 逻辑集中在服务文件中，可以后续替换。

## 编码约定

- 保留原模板的 routers / crud / models / schemas / config 分层思路。
- Python 使用明确的函数和 SQLAlchemy 查询，不使用微服务、复杂通用基类或任意 SQL 执行器。
- Vue 按页面拆分，App.vue 只保留路由出口。
- 所有请求统一使用 Axios；用户输入按纯文本渲染；AI 回答支持 Markdown 排版，但禁用原始 HTML、图片和链接，避免脚本注入及自动加载外部资源。
- 所有案件、材料、会话接口在后端检查归属，不依赖前端隐藏按钮保证权限。
- 模型失败显示真实错误提示，不返回伪造结果。敏感配置与供应商原始错误不返回浏览器。
- 用户业务事实以数据库为依据；模型仍可能推断错误，页面必须明确提示核实。
- 案情或材料变更清除旧的结构化分析，避免把旧版本结果当成当前结论。

## 验收流程

注册并留痕 → 新建案件 → 添加材料 → AI 查库问答 → 刷新后回看 → 继续咨询 → 删除会话/案件 → 退出后旧凭证不可用。

用两个账号验证互相无法查询或修改对方案件、材料和会话。模型缺少配置、返回错误和无效 JSON 时，原数据不应变成虚假的成功结果。
